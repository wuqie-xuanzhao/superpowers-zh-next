# 指令构造术

## 概述

**核心原则：定方向不定步骤，定标准不定做法。**

好的 AI 指令像一个优秀的项目 brief——告诉 AI "做什么样的人、往哪走、边界在哪"，而不是"先做 A 再做 B 然后 C"。AI 的创造力远超逐步指令的极限，放开手让它跑，用约束圈住它的边界。

## 何时使用

- 为 AI 编写任务指令（代码、设计、写作、教学、分析等）
- 优化已有的 prompt
- 批量生成同类任务的指令模板

## 指令五段结构

每个指令由五个板块组成，按顺序排列：

```
个性 → 角色 → 目标 → 成功标准 → 约束条件
```

### 1. 个性（Personality）

定义 AI 的工作态度和质量标准。不是礼貌地请求，而是设定不可妥协的底线。

**写法要点：**
- 用绝对语气，不用商量语气
- 定义"做到什么程度才算完"
- 列出不允许的偷懒行为

<Good>
```
在 AI 的世界里，完成度的边际成本几乎为零。那就全部都做。做得彻底。
做得正确。带上测试。带上文档。做得让人真心佩服，不是礼貌地点点头。
永远不要说"先放一边"，当真正的解决办法就在眼前。
标准不是"差不多就行"——是"彻底搞定了"。
```
语气强硬、标准明确、反偷懒清单完整
</Good>

<Bad>
```
请尽量做得好一点，认真完成任务，注意质量。
```
商量语气、标准模糊、没有底线
</Bad>

**个性模板：**
```
在 AI 的世界里，完成度的边际成本几乎为零。那就全部都做。做得{态度形容词}。
做得{质量标准}。{专业要求1}。{专业要求2}。
永远不要{偷懒行为1}，当{正确做法}就在眼前。
永远不要{偷懒行为2}，当{正确做法}触手可及。
标准不是"{低标准}"——是"{高标准}"。
```

### 2. 角色（Role）

定义 AI 的专业身份、适用场景和目标受众。一个具体的角色胜过十个泛泛的要求。

**写法要点：**
- 明确专业领域和经验层级
- 定义产出物的使用场景
- 指定目标受众（决定内容深度和表达方式）

<Good>
```
你是一位资深前端设计师，对生物科学拥有扎实的专业知识。
你的设计适用于课堂投影、教师讲解和学生理解。
你的作品应视觉清晰、技术正确、适合初中年龄段，并适用于现场教学。
```
领域（前端+生物）、场景（课堂投影）、受众（初中生）三维锁定
</Good>

<Bad>
```
你是一个专业的设计师，请帮忙做一个关于两栖动物的页面。
```
领域模糊、无场景、无受众
</Bad>

**角色模板：**
```
你是一位{经验级别}{专业身份}，对{专业领域}拥有扎实的专业知识。
你的作品适用于{使用场景}，服务于{目标受众}。
你的作品应{质量形容词1}、{质量形容词2}，适合{具体用途}。
```

### 3. 目标（Goal）

一句话说清要产出什么。不发散，不罗列，不解释为什么。

**写法要点：**
- 动词开头："制作"、"编写"、"设计"、"分析"
- 包含产出物类型（文档/代码/课件/报告）
- 包含主题但不展开内容

<Good>
```
制作适合课堂投影的单页交互式 HTML 课件，充分解释教学主题：两栖动物。
```
产出物类型（单页HTML课件）+ 主题（两栖动物）+ 用途（课堂投影）
</Good>

<Bad>
```
做一个关于两栖动物的东西，包括它的生活习性、分类、繁殖方式等等，
最好能用到一些图表和动画，让学生更容易理解。
```
动词模糊、展开内容（应该让 AI 自己决定）、混入约束
</Bad>

**目标模板：**
```
{动词}{产出物描述}，{核心意图}：{主题}。
```

### 4. 成功标准（Success Criteria）

可验证的完成定义。AI 说"我做完了"时，按这个清单检查。

**写法要点：**
- 每条可客观判断（通过/不通过）
- 覆盖完整性和正确性
- 不超过 5 条

<Good>
```
- 课件完整且可直接运行
- 教学顺序从引入到总结连贯
- 图表和文字内容同步正确
- 最终产出包含使用说明
```
4 条，每条可 pass/fail，覆盖完整+正确+可用
</Good>

<Bad>
```
- 质量要好
- 内容要丰富
- 要有创意
- 学生要喜欢
```
主观判断、无法验证
</Bad>

**成功标准模板：**
```
- {产出物}完整且{可运行/可交付}
- {核心流程/逻辑}{连贯/正确}
- {关键要素}{同步/一致}
- 最终产出包含{交付物清单}
```

### 5. 约束条件（Constraints）

划定边界——什么不能做、什么必须遵守。这是防止 AI 跑偏的最后一道防线。

**写法要点：**
- 硬约束用"必须/不允许"
- 软约束用"优先/倾向于"
- 包含技术和内容边界
- 包含风格和格式要求

<Good>
```
- 所有图形元素和文字需要足够大，便于投屏
- 内容仅限初中教学大纲，不超纲
- 不枯燥，图表文字相结合，表现形式多样
- 主题内容适合 40 分钟讲解的广度和深度
```
技术约束（投屏尺寸）、内容边界（初中大纲）、风格要求（不枯燥）、时间约束（40分钟）
</Good>

<Bad>
```
- 做好看一点
- 内容准确
- 不要太长
```
模糊、无具体边界
</Bad>

**约束条件常见维度：**

| 维度 | 示例 |
|------|------|
| **格式** | 单页 HTML、Markdown、不超过 2000 字 |
| **技术** | 无外部依赖、纯前端、兼容 IE11 |
| **内容边界** | 不超纲、不涉及政治、仅限 2020 年后数据 |
| **受众** | 初中生、非技术人员、管理层 |
| **风格** | 不枯燥、专业但不学术、口语化 |
| **时间/规模** | 40 分钟讲解、3 分钟阅读、适合 A4 打印 |
| **资源** | 不使用网络图片、用 GPT Image 生成、不用 SVG |

## 完整模板

```
#### 个性

在 AI 的世界里，完成度的边际成本几乎为零。那就全部都做。做得{态度}。
做得{标准}。{专业要求}。{专业要求}。
永远不要{偷懒行为}，当{正确做法}就在眼前。
标准不是"{低标准}"——是"{高标准}"。

#### 角色

你是一位{经验级别}{专业身份}，对{领域}拥有扎实的专业知识。
你的{产出物}适用于{使用场景}，服务于{目标受众}。
你的作品应{质量要求1}、{质量要求2}，适用于{具体用途}。

### 目标

{动词}{产出物}，{核心意图}：{主题}

#### 成功标准

- {产出物}完整且{可运行/可交付}
- {核心要素}{连贯/正确}
- {关键质量}{达标}
- 最终产出包含{交付物}

#### 约束条件

- {格式约束}
- {内容边界}
- {风格要求}
- {规模/时间约束}
- {资源/技术约束}
```

## 质量检查

写完指令后，逐条检查：

- [ ] 个性板块有 3 条以上"永远不要"（反偷懒底线）
- [ ] 角色包含专业身份 + 使用场景 + 目标受众
- [ ] 目标是一句话，不展开内容细节
- [ ] 成功标准每条可客观判断 pass/fail
- [ ] 约束条件覆盖了至少 3 个维度
- [ ] 整体指令没有"先做 A 再做 B"的逐步指令——只有方向和边界
- [ ] 指令不依赖特定的 AI 工具能力（通用可用）

## 最终规则

```
方向 > 步骤 —— 告诉 AI 往哪走，不告诉它每步怎么迈
约束 > 指令 —— 划定边界比罗列动作更有效
标准 > 描述 —— 可验证的完成定义胜过形容词堆砌
```

没有你的人类伙伴的许可，没有例外。
