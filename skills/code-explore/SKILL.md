# 代码探索

## 概述

同一个问题第一次花两小时查代码，第二次应该五分钟内找到答案——前提是第一次做完留下证据化的记录。

code-explore 把"提问 → 读代码 → 得结论"沉淀成可检索的探索文档，产出存放在 `docs/superpowers/explore/`。

本技能只负责"看到了什么"的证据化记录。用户意图是别的（拍板 / 处方 / 修 bug）让用户选对应技能。

## 何时使用

**应该使用：**
- 新人入仓快速理解模块边界 / 调用链 / 入口
- 用户提具体问题但暂时不要求产出方案或修复
- 功能设计或 bug 分析前先补一轮证据化探索
- 技术方向还在讨论，需要轻量 spike（只探索不拍板）

**不适用：**
- 用户已经知道要做什么（用 `writing-plans`）
- 用户要修 bug（用 `systematic-debugging`）
- 用户要做新功能（用 `brainstorming`）

## 三种探索类型

| 类型 | 适用情境 |
|------|----------|
| **question** | 围绕一个具体问题查代码并给结论 |
| **module-overview** | 快速梳理某模块结构 / 边界 / 入口 / 依赖 |
| **spike** | 对多个可能方向做轻量技术探查（不做最终决策） |

## 工作流

### Phase 1：收敛探索问题

最多两个问题：

1. "你最想先回答的一个问题是什么？"
2. "希望聚焦哪个模块 / 目录？"

用户描述已清楚直接进 Phase 2。

### Phase 2：查重叠

搜索 `docs/superpowers/explore/` 下已有的探索文档：

- 命中相近旧文档时先读它，能直接回答就告诉用户"已有一份在 {路径}，复用还是重探一遍？"
- 旧文档结论可能过期：代码已变导致旧结论失效时，在旧文档顶部标注 `> ⚠️ 此文档可能已过期`，新建一份替代

### Phase 3：证据化探索

- 用 Glob / Grep / Read **真实读代码**，不靠猜
- 边读边积累证据；**同步思考每条证据支撑哪个结论**——不支撑任何结论的证据不记录
- 关键证据 3-8 条，每条都标注 `文件:行号`
- 多模块协作或 `module-overview` / `spike` 类型 → 准备一张 Mermaid 图放在速答节
- 形成初步结论后主动检查：已有证据能否说服持怀疑态度的人？够了就停，不必扩大搜索

为什么"够了就停"：探索不是穷举，是建立到"读者能信"为止的证据链。继续扩大只会让文档变长而不变可信。

### Phase 4：起草与确认

- **先写速答节，再回填关键证据**——先有结论再回头看证据是否真支持
- 一次性起草完整文档，用户 review 后确认
- 有修改按反馈修订后再落盘

### Phase 5：归档

- 写入 `docs/superpowers/explore/YYYY-MM-DD-{中文标题}.md`
- 给出下一步建议（"要不要基于这份探索去设计方案"）。用户说"不用"就跳过。

## 文档格式

frontmatter / 正文结构 / 各节写法说明和示例见 `references/template.md`。核心约束：

速答节是整个文档最重要的部分——大多数人只看这一节。

| 规则 | 好的 | 差的 |
|------|------|------|
| **结论前置** | "模块入口是 X，核心流程是 Y → Z" | 先列 20 行文件再给结论 |
| **可操作** | "新增 handler 加到 routes/index.ts 第 42 行" | "大概在 routes 目录里" |
| **有架构图** | module-overview/spike 附 Mermaid 图 | 纯文字描述模块关系 |
| **标注置信度** | "confidence: medium——未覆盖测试文件" | confidence: high 但只看了 2 个文件 |

## 置信度标准

| 等级 | 含义 | 何时使用 |
|------|------|----------|
| **high** | 读了核心代码，结论有充分证据 | 证据 ≥ 3 条且覆盖关键路径 |
| **medium** | 读了部分代码，方向正确但细节可能有出入 | 只看了入口/接口，没深入实现 |
| **low** | 基于间接证据推测，需要进一步验证 | 只看了配置/类型定义，没看运行时逻辑 |

证据不足时 confidence **必须**降级。写 high 但只看了 2 个文件 = 欺骗读者。

## 反模式

| 反模式 | 为什么是错的 |
|--------|-------------|
| 不读代码直接给结论 | 结论是猜的，不可信 |
| 证据只写"看起来像"不写 `file:line` | 读者无法验证 |
| 结论写在证据之后 | 速答节必须在关键证据节之前 |
| 证据节比速答节长数倍 | 精简证据，不支撑结论的删掉 |
| 跨模块流程没 Mermaid 图 | 只靠文字描述无法理解流转 |
| 提前拍板 | explore 只记"看到了什么"，不下"以后应该怎么做" |
| 旧探索已过期却继续引用 | 不做标注就引用等于传播错误信息 |

## 验证清单

在标记探索完成之前：

- [ ] 已明确探索问题与范围
- [ ] 速答节给出核心结论（结论前置）
- [ ] 关键证据 3-8 条，每条标 `file:line` 并说明支撑哪个结论
- [ ] module-overview / spike 类型的速答节有 Mermaid 图
- [ ] confidence 与证据充分程度匹配
- [ ] 文档已归档到 `docs/superpowers/explore/`
- [ ] 已给出后续建议

## 最终规则

```
先读代码再给结论——结论必须回溯到 file:line
速答前置——读者先看结论再看证据
够了就停——证据链建立到"读者能信"为止
不拍板——explore 只记"看到了什么"
```

没有你的人类伙伴的许可，没有例外。
